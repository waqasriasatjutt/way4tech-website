Every print in standard Odoo is three steps: press Print, wait for the PDF to open in the browser, then pick the printer and print again. At a front desk that prints forty invoices a day, or a packing station that prints a delivery slip for every parcel, those extra clicks add up, and the wrong printer or the wrong scale gets picked often enough to waste paper and labels. Direct print removes the middle step: you press Print, and the document comes out of the printer that belongs to that desk.

This is the second chapter of the [Odoo label printing guide](/odoo-guides/odoo-label-printing/). It covers the Direct Print module on its own, and what changes when it is installed together with the Label Designer.

## What standard Odoo does

Odoo prints reports as PDF files opened in the browser. For printing without that step, Odoo's own answer is its IoT system: an IoT device connected to the printers, set up as described in the [Odoo documentation on connecting a printer](https://www.odoo.com/documentation/19.0/applications/general/iot/devices/printer.html). If you already run IoT, that may be enough. Direct Print is for businesses that want silent printing without that hardware, on Odoo 19 Community, and with rules about which desk prints what.

## How Direct Print works

There are two ways a job reaches a printer:

- **Through a print agent.** A small program on a Windows, Linux or macOS computer in your building fetches jobs from Odoo and prints them on the printers that computer can see, or on a network printer by IP address. The agent calls Odoo over HTTPS; Odoo never calls the agent. Nothing changes on your firewall, and Odoo can run in the cloud.
- **Straight from the Odoo server.** A network label or receipt printer that the server itself can reach gets its ZPL or ESC/POS directly on port 9100. Nothing is installed. The server only connects to the ports you allow in Settings.

There is no cloud print service in between and no monthly fee. The module costs USD 79 once. The two free companions, Direct Print for Inventory and Direct Print for Invoicing, add automatic printing when a transfer is validated or an invoice is confirmed.

## Step 1: install the print agent

Do this once per computer that prints. It takes about ten minutes.

1. In **Printing, Configuration, Settings**, press **Download the agent** and unzip it on a computer that sees your printers, for example into `C:\Program Files\WT Print Agent`.
2. Install Python 3.10 or newer from python.org. In the agent folder, run `python -m pip install -r requirements.txt`.
3. In **Printing, Configuration, Print Agents**, create the agent and press **Pair**. Odoo shows a one-time code and the command to run with it. The code works once and for 30 minutes. In exchange the agent receives its own token; Odoo keeps only a fingerprint of it.
4. On Windows, run `powershell -ExecutionPolicy Bypass -File install-windows.ps1` so the agent starts with Windows. On Linux, use the systemd unit in the zip.

**Revoke** on the agent form stops it at once. If a laptop is lost or a computer is replaced, revoke the old agent and pair the new one.

## Step 2: add your printers

In **Printing, Configuration, Printers**, add each printer and say two things about it.

**What it prints.** Documents (PDF) for office and laser printers, ZPL for Zebra and compatible label printers, ESC/POS for receipt printers, or Raw, which sends the bytes as they are.

**How Odoo reaches it.** Through a print agent, either as a printer installed on the agent's computer (picked from the list the agent reports) or as a network printer by IP address and port. Or straight from the Odoo server, for a network printer the server can reach.

<Shot src="/odoo-guides/odoo-direct-print-without-preview/printers.webp" alt="Printers list in Odoo with an office LaserJet and a Zebra ZD421 through the agent, a Zebra GK420d reached from the server showing Last job failed, and an Epson receipt printer by IP address" width={1600} height={1000} caption="An office laser, two Zebras and a receipt printer, each with its state." />

Then press **Print a test page** on every printer. For a PDF printer it prints a page with a 100 mm line, so you can measure that the scale is right. A ZPL printer gets a test label and an ESC/POS printer a test slip.

## Step 3: write the printing rules

A rule names a printer and the number of copies. It can be narrowed to one report, one user and one workstation. A workstation is a place people print from: the front desk, the receiving desk, a packing station.

When someone prints a report and a rule matches, the job goes to that printer and a note on screen says where it went. When no rule matches, the PDF downloads exactly as before. So you can start with one rule for invoices and add the rest later.

When several rules match, the most specific one wins. A workstation counts 4, a user 2 and a report 1; ties go to the rule with the lower sequence. In practice that means invoices printed at the front desk go to the front desk printer, while everything one person prints can follow them to their own printer elsewhere.

Each person chooses their workstation, and whether to print without the preview at all, under their avatar, **Preferences, Printing**.

<Shot src="/odoo-guides/odoo-direct-print-without-preview/rules.webp" alt="Printing Rules list with rules for invoices, delivery slips, picking operations and product labels per workstation and per user, plus automatic rules when an invoice is confirmed and when a transfer is validated, with copies and specificity" width={1600} height={1000} caption="Rules per report, per workstation and per user, and the automatic ones." />

With the free companions installed, a rule can also have a trigger: **when a transfer is validated**, filtered by operation type, or **when an invoice is confirmed**, filtered by journal. The delivery slip then prints the moment the delivery is validated, and the invoice when it is posted. If such a print fails, the document gets a note in its chatter, and the validation is never undone.

## Step 4: watch the print queue

**Printing, Print Queue** lists every job with its document, printer, sender and status. This is where you look when someone says the printer did nothing.

- A job that fails is tried again after 30 seconds, 2 minutes and 10 minutes. After that it is marked failed, with the reason on the line, such as the printer not being reachable at its address.
- Select failed jobs and press **Send again** once the printer is back.
- A job the agent took but never confirmed goes back to the queue after 10 minutes.
- Printed jobs are deleted after 30 days.

## Labels straight to the printer

With both Direct Print and the Label Designer installed, the free Print Suite module installs itself and joins them. Three things change:

1. The label dialog gets a printer field and a **Send to printer** button. A ZPL printer receives exactly the ZPL of the design; a document printer receives the PDF.
2. Each label template can have a **Default printer**, so roll labels go to the Zebra at receiving and the A4 price tag sheet goes to the office laser without anyone choosing.
3. A rule for validated transfers can print labels instead of a report. A receipt of 12 units then prints 12 labels at the receiving desk the moment it is validated.

<Callout title="Test on your own printers first">Direct Print was tested end to end with the agent on Windows 11 printing to "Microsoft Print to PDF" and to a simulated network printer. It has not been run on every printer model. Print a test page on each of your printers, and one real document or label per rule, before going live. The agent is a Python program, so Python 3.10 or newer must be installed on the computer that prints. Printers shared from another Windows computer are only seen when the agent runs as the signed-in user, which is the default.</Callout>

## A sensible order for go-live

1. Pair one agent on the computer that already has the printers installed.
2. Add the printers and print a test page on each. Measure the 100 mm line.
3. Write one rule: invoices at the front desk. Let people use it for a day.
4. Add the delivery slip rule for the packing station, then the automatic rules for validated deliveries and confirmed invoices.
5. If you have the Label Designer, set a default printer per template and add the labels on receipt rule last, once the receiving team trusts the counts.
6. Check the print queue daily for the first week. A failed job with the same reason twice usually means a printer address or port that changed.
